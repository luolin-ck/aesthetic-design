# 1.0.0 — Initial versioned release

## Problem and scope

The existing package had no version or change log, and its integrity validator accepted that unversioned state. Publishing the entire research collection would also redistribute restricted/NC or uncertain media. Earlier research is an unversioned baseline; no historical tests or releases were reconstructed.

## Logical changes and acceptance

- Add VERSION, matching SKILL/manifest metadata, bilingual changelog and per-release records, and the test-first maintenance contract.
- Extend both equivalent offline validators with availability and release checks while preserving file/hash/link/guide/translation/image integrity.
- Add six standard-library mutation tests: version increase, missing version/log, stale metadata/invalid Red evidence, missing/unapproved public images, restricted/NC media, and secret/path/symlink rejection.
- Separate private-complete (43 images) and public-conservative (9 images, 34 explicitly withheld) profiles. All 36 textual guides and 43 provenance records remain; only 8 directions have public offline images and 28 lack them.
- Add original-work MIT scope and third-party notices, exact media rights decisions, source/attribution retention, and privacy/forbidden-file checks. Preserve the chair’s embedded Beatrice Pinto credit without inferring its role.

## Actual Red evidence — 2026-11-06

Before implementation, the baseline `python3 scripts/validate_offline.py` returned 0, 208 files / 36 styles / 43 images, despite VERSION and CHANGELOG both being absent. The new acceptance expected rejection (nonzero). The actual assertion failed with exit 1 at 04:53:48 UTC. This is the demonstrated metadata defect, not a visual-style failure. The raw result is summarized in the JSON companion. The subsequently written mutation suite initially failed to import the not-yet-existing checker; this is only implementation-order evidence, not an independent semantic defect.

## Actual Green evidence — 2026-11-06

After implementing the shared checker, `python3 -B -m unittest discover -s tests -v` ran all six mutation tests and returned 0. The final complete package checks also run both language validators for each profile, read-only and with socket access disabled. The private profile passed with 222 listed files, 44 translation pairs, 43 images and 1684 local links; the public profile passed with 189 listed files, 44 pairs, 9 images and 1662 local links at the first complete run. Final checks are rerun after documentation changes; counts are reported by the validators, not treated as an authentication or classification benchmark. The metadata checker cannot prove evidence truthful; recorded outputs need human review. No hosted workflow/dependency was added.

## Limits and rollback

Automated checks validate metadata, availability, bytes and rejection boundaries, not copyright clearance or style accuracy. The first public allowlist is deliberately conservative and leaves 28 directions without local visual comparators. No live Codex/Claude activation, controlled classification experiment or universal legal clearance was tested. Scripts do not fetch missing files. The earlier complete private archive was retained before implementation; restore a verified complete version or later Git tag and rerun validation to roll back, retaining this record. No public repository or external state was changed by implementation.

## Prepublication review correction — 2026-11-06

Independent final review rejected four remaining public coverage claims: correspondence-review and selection-review prose described a current 43-image library, catalog scope said 43 images, and selection-review JSON left current_image_count unscoped. These fields could mislead a reader consuming them independently. Each is now limited in place to the reviewed source collection on 2026-11-05; public JSON also declares the actual 9 included / 34 withheld / 8 directions with images / 28 directions without images. The historical 43-image fact is retained. No image or code changed.

A temporary read-only assertion checked these four independent consumption points against actual catalog availability. At 05:23:45 UTC all four failed (expected exit 0, actual exit 1); after the correction, the same assertion passed all four at 05:24:22 UTC (exit 0). This is additional real Red/Green evidence for the first 1.0.0 release, before publication, not an invented earlier release or a new 1.0.1. Both distribution manifests and the private archive were refreshed and relevant integrity checks rerun. Previous media-rights and unchanged code-test results remain applicable.
